# Modernização visual 2.0 — revisão isolada

## Base e preservação

Branch de revisão: `codex/layout-2-0-operacional`, criada de
`codex/modernizacao-visual-runtime` (`6e77e35`). O código operacional não commitado
foi preservado separadamente em `0892127`, com hashes em `layout-2-0-base.json`.
Esse primeiro commit contém funcionalidades anteriores; não é mudança de backend
para o layout. Depois dele, os commits visuais alteram somente frontend, testes,
documentação e o script de revisão. Nenhum banco real, segredo, upload, backup,
outra worktree operacional ou configuração de produção foi alterado nesta etapa.

## Inventário e decisões

O App usa seleção de módulos por estado e imports lazy, sem React Router.
Foram conservados os destinos de consulta, as permissões, a confirmação de saída,
rascunhos, filtros, formulários e impressão. Navegação existente por seis grupos,
SVGs ModuloIcon, cards e premium.css foram reutilizados. Tailwind prefixado foi
preservado. Nenhuma dependência de produto foi adicionada.

Telas inspecionadas: Painel e seus quadros/mapa; propriedades no App; Talhões;
produção/saldos; cargas e seus resumos; cadastros/CAD-PRO; Vendas; Mercado e gráfico;
Clima; Máquinas; Transportes; Assistente e ChatLocal. O padrão global de superfície,
tipografia, controles e tabelas também se aplica às demais telas existentes.

Pontos encontrados: Suspense envolvia todo o shell e retirava a navegação durante
troca de telas; alertas ficavam depois de cartões altos de mercado; o SVG de 720 px
encolhia texto no celular; Vendas tinha overflow lateral de 35 px na fixture desktop.
Foi preservado o carregamento separado dos módulos e do Leaflet. Não foi realizado
benchmark de carga, rede operacional ou duração das consultas de banco.

## Verificações

- `npm test`: aprovado, incluindo autenticação/logout, rascunhos, usabilidade,
  permissões, geometria/coordenadas, submissão, romaneios, impressão financeira,
  holerite e novos testes de composição/baixa física/navegação por permissão.
- `npm run build`: TypeScript e Vite aprovados. Build final: 262 módulos,
  JS inicial 233,31 kB (73,39 kB gzip), CSS comum 133,89 kB (28,77 kB gzip).
  São tamanhos de artefatos, não um benchmark de velocidade no computador do usuário.
- Revisão headless isolada com Edge/Playwright: APIs interceptadas; conta, preços,
  chuva e registros fictícios identificados nas capturas; zero acesso a banco real.
- Painel em 1440, 1366, 768 e 390 px; propriedades, talhões, produção/saldos,
  vendas, mercado, clima, máquinas, transportes e assistente em desktop e 390 px.
- Ausência de scroll horizontal da página nas capturas novas; tabelas conservam
  scroll interno. Antes/depois incluídos, inclusive estado vazio, erro, permissão
  restrita e dados antigos. Conferência de Ctrl K/Escape e logout da prévia.
- Composição/fluxo novos ocultos em print; PDFs demonstrativos A4 de saldos e
  vendas gerados. Não é impressão física nem revisão integral de todos os relatórios.
- Script reproduzível: `scripts/revisao_visual_layout.mjs`, com Playwright externo
  já disponível no ambiente de ferramentas; não faz parte do bundle do produto.
- Diff visual após `0892127`: sem backend/migrations. Revisão final de arquivos,
  credenciais e temporários antes do envio.

## Pendências que impedem aprovação de merge

1. A base operacional preservada contém campos agronômicos de produtos introduzidos
   em uma tarefa simultânea e ainda sem migration no momento da cópia. A suíte de
   correções históricas teve seis erros de coluna ausente por essa condição. O layout
   não cria/aplica migrations nem modifica essa regra; base deve ser estabilizada
   antes de integrar. Um erro TypeScript do token ADAPAR write-only foi corrigido
   separadamente em `e23d43a`, sem alterar a regra de negócio.
2. Validação funcional autenticada com dados reais, salvamento persistente, bloqueios
   de venda/saldo, transferências/CAD-PRO e geometrias KML reais não foi realizada nesta
   revisão visual. Os testes existentes do frontend passaram; isso não substitui API E2E.
3. Navegador integrado falhou na inicialização dos assets. Headless isolado foi usado;
   acesso externo da foto e mapas/satélite deve ser conferido no navegador operacional.
4. Docker build encontrou falha de DNS do Docker Hub. Verificação final foi realizada
   com dependências locais copiadas para o checkout isolado, sem atualizar o ambiente.

PR deve permanecer em rascunho, com alvo operacional. Sem merge em main ou produção.
